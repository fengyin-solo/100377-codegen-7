# 水文监测站网管理系统

面向水文监测站点运行、水位流量雨量数据采集、遥测设备维护与数据整编发布的水文站网管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 断面成组复测

断面测量页提供「成组复测台」，业务规则集中在 `frontend/src/api/retest-service.ts`：

- **同河成组**：表格多选同一河流的断面后统一安排重测；可安排状态为「已测量 / 待校核 / 需重测」，
  跨河流选择会被拒绝。
- **组内混合单位**：同一河流允许跨「管理单位」混编，创建时提示涉及单位，校核清单按单位分列责任。
- **校核清单**：清单 = 本次选中的断面 + 同一条河上所有历史「待校核」断面（即使本次未选中也兼容纳入）。
- **站房配合待办**：批次落库时按涉及站房在站房维护模块各新增一条「复测配合」待办，可在站房页统一安排。
- **部分失败不回滚**：复测按断面逐条独立落库；某条复测失败保留在未完成处，可单条重试或
  「从未完成处继续」，其他断面已完成结果不回滚。
- **统计口径可调整**：窄口径只统计本次重测产出的待校核；宽口径按整条河校核清单统计（含历史待校核）。
  切换口径立即重算所有**未归档**批次的复测摘要；已归档批次冻结归档瞬间的口径与快照，不再重算。
- **复测摘要保留**：批次落库后无论刷新页面还是从其他路由返回，顶部复测摘要（最近批次 + 进行中批次）都保留。
- **并发只生效一次**：幂等键为「计划日期 + 河流 + 断面集合」，叠加跨标签页 localStorage 互斥锁与
  进程内提交队列。两个终端（或双击）并发提交同一安排时，只有一次落库，另一方直接拿回已生成的批次。
  复测台弹窗里的「模拟双终端并发提交」按钮可自测该行为。

复测批次、统计口径与跨终端锁存放在 localStorage 键
`hydrology-monitor-station:retest`（锁为 `…:retest-lock`），与业务记录的 `…:entries` 分开。
清掉 `…:entries` 只重置业务记录，复测批次需另清 `…:retest`。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydrology-monitor-station:entries` 这一项，或调用 `resetModule(模块)`。
